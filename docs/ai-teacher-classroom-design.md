# YouTube 单节 AI 老师课堂设计

日期：2026-11-09。状态：核心课堂流程已实现，以下保留设计说明及实现记录。适用范围：YouTube 导入文章的单节学习入口；正式客户端 Windows、Android，并保留 Web 演示版兼容。调试以标准 Windows 客户端为准。

实现更新：2026-11-10。标准 Windows 原生流程已通过真实 Gemini 与合成语音验证；前端测试 923 项通过，Rust 230 项通过（9 项原有网络测试跳过），Content Studio 校验通过。

## 1. 产品目标

每一节是一堂可以随时插话的小课。AI 根据提前生成的教学大纲主动讲解，结合本节原文、原声和学习者水平解释词汇、表达及句意。学生可以用语音或文字暂停、提问、要求重讲；答疑后由学生明确说“继续”，老师从中断处接着讲，直到完成本节。

推荐名称：**AI 老师课堂**。原文章的“学习”按钮改为“进入课堂”；有课堂记录时显示“继续上课”；完成后显示“复习本节”。

课堂边界是当前章节。课堂结束后返回文章中的本节位置，可继续听读或进入下一节；不自动跨节开课。

## 3. 一堂课怎样进行

1. **课前准备**：显示本节标题、原视频区间、学习目标与预计课时；时间是按大纲估算，不含自由答疑。提供“开始上课”，首次开麦时申请系统权限；拒绝权限仍可文字提问。
2. **开场**：老师用一句话介绍情境和目标，例如：“这一节我们学会表达什么时间对自己方便，先看视频里的这句话。”
3. **逐点讲解**：按大纲讲解，每次一个短小教学单元。先放原句，再解释意思、用法、易混点，必要时补一个贴近生活的例子。无需学生反复点“下一页”。
4. **穿插语音互动**：在讲解的自然停顿处邀请学生复述、回答、造句或做一轮情境对话；不把每个知识点都变成考试。等待回答时停止自动推进，提供“跳过这次互动”；学生也可选择本节“只听讲解”。正常作答后老师简短反馈并自然接着讲。
5. **随时插话**：学生开口或发文字，老师停止当前讲解并处理请求。可以连续追问；答疑不改变主线课程游标。
6. **继续主线**：学生说“继续”或点击“继续上课”，老师简短接回：“刚才讲到……我们接着看……”
7. **课堂结束**：总结重点、个人疑问和待复习项，显示“返回原文”“复习疑问”“下一节”。进入下一节仍由学生主动触发。

### 教师行为约定

- 默认用学习者母语解释，用目标语言读原句、示范和练习；语速、难度根据 CEFR 调整。
- 每个教学小段约 15–30 秒，属于设计目标，需真实语音试教后调整；不能一次生成整节长演讲。
- 原文事实以本节字幕为依据；教师补充的例句标明“补充例句”。对不清楚的字幕或视频画面不作确定推断。
- 提问时先直接回答，再决定是否需要一个例子；保持简短，允许追问。
- 学生主动打断、提问后，仅在学生明确“继续”后回主线；提问后的沉默不视为继续。“好”“嗯”等模糊表达不自动恢复。老师发起的练习正常作答或明确跳过后，可反馈并自然继续。
- “换个例子”“讲慢一点”“再解释一次”属于当前点的辅助教学，完成后同样等学生继续。
- “继续”是当前状态下的控制意图；如果学生正在举例或讨论这个词本身，不按关键词直接切换状态。文字按钮是确定性的恢复入口。
- 学生只说“暂停”时不再播放口头确认，界面显示“已暂停”；暂停后语音控制仍可用，静音麦克风是另一个独立操作。

### 自然讲解的具体要求

大纲记录“要教会什么、依据哪句原文、关键知识点、可用例子与可选互动”，不存储要求逐字朗读的完整教师台词。Live 在同一会话中结合已讲内容、学生反应和当前目标组织措辞，直接生成语音。

- 可以先举例再解释，也可以从学生刚才的问题过渡到下一个相关知识点；按理解情况增减解释和例子，但不遗漏本节必讲目标。
- 记住学生已经理解的内容、问过的问题和出现的困难。已解释清楚的点少重复；学生不理解时换一种说法，而不是重放相同台词。
- 使用自然的衔接、停顿和语气；不朗读内部节点名、编号、工具指令，不在每个小段重新问候或机械宣布进入下一步。
- 原设计中的 15–30 秒是控制讲解密度的参考，不是硬性计时截断。教学小段是内部断点，界面和语音不必显露这些分段；完整句子和自然衔接优先。
- 本地控制器提供当前教学意图和状态，不连续塞入预写台词。板书只展示重点，不把整段口头讲解当作板书供老师照读。

自然度需要真实试教验收：同一大纲可以有不同措辞；学生中途表示不懂后，老师能调整讲法；恢复授课时能联系刚才的问答自然衔接。示意中的固定文本仅用于演示界面状态，不代表正式课堂的生成方式。

### 讲解中的可跳过语音互动

互动属于课堂讲解的一部分，不单独切到口语练习模块。老师可在适合的位置自然邀请，例如：“我们刚学了这个表达，你试着问我明天方不方便？”学生用语音作答，老师听完后给一句简短反馈，必要时示范，再继续主线。

可使用四类轻量互动：跟读一句、回答一个理解问题、换一个时间或人物造句、围绕原文情境对话一两轮。优先围绕本节原句设计，每次一个小任务，避免在每个词之后要求开口。

两种选择分别保存：

- **跳过这次互动**：说“跳过”“先不练，继续讲”或点击按钮。结束当前互动，直接进入后续讲解，不跳过该知识点尚未讲完的内容；不计答错，也不计已掌握。
- **本节只听讲解**：课前或课中都可切换。关闭后续主动练习邀请，仍保留学生语音／文字提问和暂停能力；随时可以重新开启互动。这个偏好与麦克风开关独立。

老师邀请后进入等待回答状态，不能边问边继续讲。学生沉默时只作一次温和提示，并保留“跳过”入口；沉默不计错误、不视为跳过，也不反复催促。用户在本次邀请后选择“只听讲解”，等价于跳过当前互动并关闭后续邀请。

正常完成老师发起的练习、或明确跳过后，教师简短反馈并自然继续，无需额外说“继续”。学生主动打断提问则按原规则：答疑后等待明确继续。练习中途提出疑问时先保存练习位置并答疑；学生说继续后回到该练习，可以作答或跳过，不把问题误判成练习答案。

首版反馈关注是否表达出目标意思、明显用法问题与可辨识的发音问题；听不清时请求重说或允许跳过，不承诺精确音素评分。

## 4. 页面与交互

采用独立全屏课堂页，而不是在原课件弹窗上继续加控制。建议路由：`/learn/reading/:id/chapters/:chapterId/classroom`；Android 返回目标为当前文章。

### 480×800 / Android / 窄 Windows

2026-11-10 Windows debug 调整：中央改为留白的动态板书；课前不展示整段原句、全部讲解要点和预写板书。Live 通过 `write_classroom_board` 在讲解时更新短原句、重点表达、用法、补充例句及练习支架，同类内容更新替换，切换知识点清空。首个音频开始后才显示排队板书，暂停／插话丢弃未播放回合的待显示内容；当前板书随课堂记录保存。教师字幕移到下方紧凑区域，记录与结束小结默认折叠。

同日重新布局：课堂采用深绿黑板、粉笔色文字与低干扰的顶部进度；板书按 `active_kind` 突出当前正在讲的内容，原句作弱化语境，不同时铺开所有已写内容。教师状态、短字幕和麦克风／开始暂停／文字提问统一在底部；输入框按需展开。语言、互动偏好、课程大纲、课堂记录与小结集中到带焦点约束和 Escape 关闭的底部面板。主画面不再常驻语言选择、配置提示或长记录。

课堂提供母语／目标语言授课选择，保存为 session 的 `teaching_language`（旧记录默认 `native`）。目标语言模式在 Live 系统指令和每轮教学意图中约束解释、问题、反馈与板书的 CEFR 难度，并将原有母语大纲视为内部参考。课中更换语言先暂停、保留断点、清除旧语言板书和会话恢复句柄，待用户继续后使用新语言建立会话。验证仅使用标准 Windows debug、测试、日志和程序调试接口，不使用 Computer Use。

- **顶部**：返回、本节名称、课程大纲入口。展开大纲可看“已讲／当前／未讲／跳过”。跳转到其他点时先暂停，不把跨过的内容算完成。
- **进度**：显示“已讲完 2 / 6 个要点”，避免把进入某个要点显示成已学完。
- **中央板书**：当前原句、高亮表达、简明释义、原声播放入口和来源时间。一次只展示当前讲解需要的材料。
- **老师区**：小型老师标识、明确状态和实时字幕。状态包括“老师讲解中”“正在听你说”“正在回答”“已暂停”“等你继续”“正在重连”。不依赖头像动画传递状态。
- **问答区**：显示最近问答，完整课堂记录按需展开。提问期间板书仍停留当前知识点。
- **底部**：暂停／继续、麦克风开关、文字输入、发送。开始输入时先暂停讲课，输入法收起后保持暂停；由学生显式继续。

老师有声音输出，文字字幕同步展示；首版字幕为近实时文本，不承诺逐词卡拉 OK 对齐。正在接收的转写不等于学生已经听到的内容。

默认不放大型数字人；先把听感、讲解和打断做稳。已有插图可作为板书素材，但课堂流程不再由卡片翻页驱动。

### 宽 Windows / TV

宽屏采用左侧大纲、中间板书、右侧问答，底部保留统一控制。布局按 `isTvLayoutMode` 选择，不以 `isTvMode` 替代布局判断。

TV 遥控器可以到达所有控制；不能假设 TV 麦克风支持持续采集。可用文字／遥控器暂停与继续，支持麦克风的设备再启用语音。课堂属于 reading 模块，不依赖 TV 上未注册的 speaking 页面。

## 5. 控制语义

| 学生动作 | 立即动作 | 后续行为 |
| --- | --- | --- |
| 讲课时开口 | 在确认本地人声后先停老师播放，保存断点 | VAD 与 Live 处理输入，转入聆听／答疑 |
| 说“暂停”或点击暂停 | 停止播放，清空队列，停止主线推进 | 保持暂停，仍允许后续提问或说继续 |
| 开始输入文字 | 暂停当前讲解 | 保留草稿，发送后进入答疑；取消输入也不擅自恢复 |
| 文字发送问题 | 本地先停音，发同一 Live 会话 | 回答后进入“等你继续” |
| 连续追问 | 中断当前回答 | 先处理最新输入，主线断点保持不变 |
| 回答老师发起的练习 | 保持当前练习与主线位置 | 简短反馈后自然继续；主动追问则先答疑并等待明确继续 |
| 说“跳过这次互动”或点击跳过 | 取消当前练习等待与相关任务 | 记为互动跳过，继续剩余讲解；不记答错或已掌握 |
| 切换“本节只听讲解” | 关闭主动练习邀请；有进行中的互动则跳过 | 保留语音／文字提问、暂停和继续能力 |
| 说“继续”或点击继续 | 校验状态与断点 | 从当前未完成小段的自然起点续讲 |
| 说“这一点我会了，跳过” | 明确记录为跳过 | 进入下一个点；不记录为已掌握 |
| 点击原声／要求回听 | 老师让出音频通道 | 播放绑定的本地原声片段，结束后按当前流程返回 |
| 静音麦克风 | 停止麦克风上传 | 老师可以继续讲；用文字或按钮控制 |
| 离开课堂／切到后台／来电 | 停音、停采集、保存断点 | 返回后显示“继续上课”，不突然出声 |

噪声造成误打断时显示“刚才没听清，继续上课？”；短声“嗯”不强行结束课程。提供“按住说话”作为设备回声控制效果不佳时的备用输入方式，不以关闭语音打断替代默认体验。

## 6. 大纲设计：课前生成，课中执行

当前已有的数据是词汇／短语的 slides，尚不是完整教学计划。应增加独立、有版本的 `TeachingPlan`，在保留旧 slides 的前提下生成。

每个教学节点包含：

| 字段 | 含义 |
| --- | --- |
| `node_id`、`order`、`kind` | 稳定标识、顺序、情境／表达／原声／练习／小结等类型 |
| `objective`、`key_points` | 这个点讲完后学生应该理解什么 |
| `source_refs` | 文章段落 ID、原句、合法的起止秒数 |
| `explanation_beats` | 若干有 ID 的教学小段：意思、例句、对比等；每段一个明确目标 |
| `board` | 原句、术语、释义、补充例句等结构化板书 |
| `practice` | 可选互动类型、学习目标、参考答案、适合邀请的时机和跳过策略；邀请措辞由老师现场组织 |
| `completion_rule` | 本点结束条件，不由“模型说讲完了”单独决定 |

大纲顶层包括语言、CEFR、学习目标、`schema_version`、`plan_version`、字幕内容 hash、生成状态。生成后检查引用段落、时间范围、必填内容和空节点，再标为可上课。

大纲包含教学意图和关键事实，Live 老师根据它自然讲解，不照读固定逐字稿。教学主线在一堂课中固定；问答可灵活拓展。大纲重新生成时保留旧版本，进行中的课堂继续绑定原版本，防止节点 ID 改变使断点失效。

2026-11-10 大纲质量调整：新生成结果使用 `schema_version: 2`，按具体表达组织节点，视频主题仅作语境，不再生成主题摘要式的课程。节点增加 `focus_expression`、双语 `examples`；`source.text` 保存从清理后字幕核对出的短引用，`source.paragraph_text` 保留完整段落，原声起止时间仍为真实段落范围。练习增加 `scaffold` 与 `answer_example`，老师先给支架、等待作答后再给参考回答。Rust 与 Web 同步拒绝虚构引用、重复表达、缺少板书／例句／练习支架的大纲；已保存的旧版本仍可读取，不自动覆盖课堂断点。

新导入文章生成教学大纲；不再为了隐藏的静态模式生成 SVG 课件。已有课件可提取 term、原句与时间戳作为生成输入，按需转换为大纲并校验，不把旧卡片观看进度直接转换成新课堂进度。

## 7. 技术结构与课堂状态

```text
本节字幕 + 语言/水平 + 已有词汇数据
                 ↓
课前内容生成模型 → TeachingPlan（结构化校验、版本化保存）
                                    ↓
课堂页 ←→ 本地 ClassroomController ←→ 通用 Gemini Live 会话
                   ↓                         ↓
         进度、板书、问答、断点          实时语音、转写、工具请求
                   ↓
            SQLite / Web IndexedDB
```

Live 老师处理听说和解释，本地控制器决定主线位置、是否推进和完成状态。课堂工具可以请求显示板书、播放绑定原声、报告当前小段完成、提交练习反馈；控制器校验计划版本、节点、会话轮次和合法状态后才执行。

Google 官方模型页列出 `gemini-3.8-live` 的语音、文字输入和工具调用能力，同时说明不支持 structured outputs。因此大纲使用现有内容生成通道，并做结构化校验；不能依赖 Live 连续输出任意 JSON 来驱动整个 UI。课堂工具调用同样必须校验参数。

### 按 Gemini 3.8 Live 实现语音互动

以下为基于官方协议的应用设计，不是已经验证过的实时课堂实现。沿用当前 Gemini Developer API 的 `BidiGenerateContent` WebSocket 接口；工具名由本应用定义，不是 Google 内置教学功能。具体 SDK 字段位置、事件顺序与兼容性在实现时用真实 3.8 Live 会话验证。

**一堂课保持同一个 Live 会话。** 系统指令提供教师风格、语言、CEFR、课堂控制约定，大纲提供目标与原文依据。学生音频持续通过 `realtimeInput.audio` 传入，老师直接返回原生音频。输入输出转写用于字幕、记录和排查，不把“先转写、再调用聊天模型、再 TTS”作为主交互链路。输入使用 16kHz PCM，输出按实际 MIME／采样率播放，当前官方原生输出为 24kHz PCM。

建议定义以下少量课堂工具：

| 应用自定义工具 | 用途 | 客户端约束 |
| --- | --- | --- |
| `begin_interaction` | 老师申请发起某个节点的一次口头互动，携带互动 ID、类型和目标 | 检查本节互动偏好与合法节点，登记 pending 邀请；工具请求不等于问题已经播完 |
| `finish_interaction` | 老师报告学生已作答及简短反馈 | 校验当前互动 ID、轮次和状态；已跳过的互动不得再写入回答结果 |
| `request_classroom_control` | 根据学生语音请求暂停、继续、跳过互动或只听讲解 | 客户端校验后执行；不允许模型任意移动进度 |

这些工具默认显式声明 `NON_BLOCKING`，并对仅登记状态的工具结果采用 `SILENT` 回应，避免一次 UI 状态登记触发老师额外开口。`SILENT` 不会停止老师当前音频，也不能保证老师主动等待，必须结合系统约定、回合结束和本地状态守卫。不要把工具请求挂起到学生回答，以长期 `BLOCKING` 调用代替等待状态。与学生说话相关的反馈由正常 Live 对话产生。

一次正常互动的时序：

1. 控制器允许当前节点进行互动，并提供“用所学表达问明天是否方便”这样的教学目标，不提供必须照读的台词。
2. 老师自然提问，并通过 `begin_interaction` 同步互动意图。调用可以与提问音频交错到达，客户端不能假设谁先谁后；学生若提前开口也可正常打断。
3. 在提问回合正常结束且本地问题音频播完后，进入 `awaiting_answer`，显示“轮到你说／跳过这次互动”。暂停课程自动推进；不主动发送下一条授课请求。
4. 学生音频仍在同一会话中连续上传。服务端 VAD 判断说话的起止，Gemini 结合当前互动理解回答，给简短反馈，并报告互动结果。VAD 检测到停顿仅表示语音活动边界，不代表学生完成课程或选择跳过。
5. 只有互动结果有效、反馈回合正常结束、反馈音频播完，才允许回主线并请求下一个教学意图。若学生是在提问，则进入答疑分支，反馈结束后等明确继续。

**跳过走同一套本地控制。** 点击按钮直接登记当前互动为 skipped；语音“跳过”由 Live 识别后通过控制工具请求执行。客户端先取消该互动的等待、自动任务和可能残留的音频，再向同一会话同步控制意图，让老师直接继续剩余讲解，不追问、不打分。文字／按钮控制可使用 `clientContent`；3.8 中设置 `turnComplete: true` 会打断当前生成，必须与本地清队列和旧回合隔离配套使用。跳过本身不会神奇清除服务端上下文，需明确通知模型当前互动已关闭。

每个互动使用唯一 ID，每次控制变更增加逻辑版本；跳过后迟到的评分、工具调用或音频不再产生副作用。切到“只听讲解”时同步偏好；即便老师迟到地请求发起互动，客户端也拒绝并返回当前策略，不进入等待。

**3.8 特有的配置与回合处理：**

- 输出使用 `responseModalities: ["AUDIO"]`，需要字幕则开启输入输出转写。不能把音频与独立 JSON 结构化输出混作一种可靠的 UI 控制通道。
- 3.8 Live 默认支持异步工具调用，与较老模型的默认行为不同；状态报告显式使用 `NON_BLOCKING` 与 `SILENT`，采用当前端点与 SDK 认可的字段和枚举，不混用不同接口的示例。
- `proactive_audio` 在 3.8 Live 中始终启用，不传 `false`；该能力让模型选择是否回应输入，不负责自动按教学大纲讲完一课。控制器仍需在合法边界调度下一次授课。
- 不传该模型不支持的 `thinking_level / thinking_config`，不添加已移除的 `enable_affective_dialog`。
- 允许用户活动打断当前老师回合；麦克风不因老师正在说话而停传。收到 `serverContent.interrupted` 时清空老师音频队列；本地确认人声可先停播以缩短感知延迟，但不能仅按音量大小判断人声。
- 分别处理 `generationComplete`、`turnComplete`、`interrupted` 与本地音频播放结束。中断回合不一定出现 `generationComplete`；`turnComplete` 也可能属于被中断的回合，不能据此记完成。转写与音频没有精确逐词对齐保证。
- 语言学习者停顿较多，VAD 的停顿阈值需要真机调校。学生静音、思考或被 proactive audio 忽略时不自动算错误／跳过，提供重新说、文字回答和跳过按钮。
- 大纲和控制信息在安全回合边界补充；不要为更新进度频繁发送会触发新生成的 client content，否则会反复打断老师。

优先验证一个真实小闭环：自然讲一句、发起一次互动、学生作答并获得反馈；随后验证语音／按钮跳过、讲课中插话、练习中提问、外放回声、迟到工具结果与重复控制。音频回合、工具回合和本地状态必须对得上，再扩展为整节授课。

### 两层状态

- 连接状态：`idle / connecting / connected / reconnecting / error / closed`。
- 教学状态：`ready / teaching / listening / answering / paused / awaiting_continue / awaiting_answer / playing_source / completed`。

连接恢复不等于恢复讲课。恢复成功先还原板书和进度，再等待“继续”。正常讲解小段完成后，由控制器检查当前状态并主动触发下一小段；不能假设一次 Live 回答会自行讲完整节。

### 断点与完成判定

持久化的断点至少包含 `user_id`、`article_id`、`chapter_id`、`plan_version`、`node_id`、`beat_id`、已完成与跳过节点集合、练习状态、简短的已讲内容摘要。另存本节互动偏好 `interaction_mode`（`guided / listen_only`）及每次互动的尝试 ID、状态（等待／已回答／已跳过）、反馈和恢复位置。跳过互动与跳过整个教学节点分别记录。

音频在内存维护生成轮次、已接收时长、已排队时长和实际播放结束事件。只有满足“该小段生成已结束 + 本地音频队列已播完 + 未被取消 + 仍处于合法教学状态”，才提交小段完成并推进。`turnComplete` 或工具完成消息本身不足以表示学生已听完。

首版保证知识点／教学小段级恢复：被打断的小段从自然起点重讲，通常会有少量重复。不承诺逐字无缝接回；不能仅凭流式转写推导精确的已听单词位置。

### 打断与竞态处理

1. 本地确认学生开始说话、点击暂停或开始输入时，立即停止已排队及正在播出的老师音频，冻结主线游标。
2. 控制器增加逻辑轮次版本，取消自动推进任务，标记旧回合为 interrupted；等待服务端中断／新回合边界前丢弃旧音频和旧副作用。
3. 语音通过 Live VAD 触发服务端中断；文字问题通过支持的 client content 提交。仅暂停时也需发明确控制消息让服务端结束当前讲解并保持静默。
4. Live 会话不存在可凭空假设的通用 cancel 命令，按实际协议实现；本地静音必须先发生，服务端信号用于同步状态，不能只调用当前 `interruptAi()`。
5. 异步工具请求按调用 ID 去重，校验与当前节点和轮次的关系。旧回合迟到的“完成节点／播放原声”不得执行。
6. 学生主动提问的回答完成且播放结束后进入 `awaiting_continue`，只有明确恢复事件可以回到主线。老师发起的互动正常作答／跳过，按互动流程反馈并自然继续。

### 音频与长会话

- 提取通用 Live 传输层，保留原 speaking 业务行为；课堂使用独立控制器与可配置工具，避免口语评分工具、问候语和总轮数约束串入课堂。
- 课堂麦克风默认关闭，由学生主动开启。老师本地音频播放期间不上传麦克风 PCM，播放自然结束或被停止后保留 500ms 余音缓冲；AudioWorklet 帧携带采集时刻，延迟送达的旧帧直接丢弃。保留系统回声消除、降噪，关闭自动增益以免放大余音。点击开麦会先暂停讲解；已开麦时可先暂停再插话，讲解结束后自动恢复输入。物理外放与蓝牙设备效果仍需设备实测。
- 统一管理老师声音、原视频／导入音频、TTS，确保只有一个教学输出通道播放。原声播放期间按设备回声表现隔离回录，始终保留按钮打断入口。
- 启用会话恢复和上下文压缩，处理 GoAway 与网络中断。有效恢复句柄优先复连；不可恢复时，用大纲版本、持久断点、近期问答摘要建立新会话。
- 新会话明确指示“恢复到某节点，等待学生继续”，避免重播开场或整堂重来。重连不重发有副作用的工具调用。
- 默认保存文字与学习结果，不永久保存麦克风原始录音。课堂关闭后释放录音设备、AudioContext 与连接。长时间暂停保存后断开，显式继续时重连。

## 8. 数据、兼容与旧模式封存

首版追加 migration 25 的 `chapter_classrooms`，不破坏现有字段：章节 ID 外键、版本化 `plan_json`、含断点／互动／文字记录的 `session_json`、并发修订号 `revision` 与更新时间。生成成功才写入大纲；并发生成不覆盖已保存大纲。每个章节保留当前课堂状态，完成后主动复习会开始新一轮。

教学大纲和来源绑定同一导入章节，不提供课中重新生成入口。文字记录限制长度，Live 请求只附带近期对话；原始麦克风录音不落盘。保存按队列串行提交，后端同时校验大纲版本、游标与 revision，拒绝过期覆盖。删除原文章时级联清理课堂记录。

正式客户端用 SQLite，Web 用 IndexedDB。新增 API 统一经过 `src/shared/api.js`，Rust commands 薄封装；WebBackend 保持相同参数及返回结构。

封存方式：保留 `CoursewareModal.vue`、旧生成函数、slides、`viewed_pages`、`total_pages` 和现有测试；用内部功能开关和路由入口控制隔离旧模式，不在设置或学习页显示切换选项。新入口不再挂载旧组件。需要回滚时可切回旧入口，不必恢复删除的数据。

新课堂“已完成”和“已掌握”分开：听完课程不自动把生词标为掌握；旧课件已学完也不自动标记新课堂完成。明确加入生词本、练习表现可复用现有词汇能力。

### Web 与鉴权边界

Windows、Android 首先复用现有多模态模型配置，但连接地址必须真实支持 Live WebSocket，不能只根据 HTTP 配置可用推断 Live 可用。

公开 Web 演示不得向浏览器下发平台长期 API key。部署时选 Google 官方短期令牌方式，或固定供应商／固定上游的无状态 Live WebSocket relay；在当前部署环境验证后确定。relay 不引入会话数据库或持久缓存，不接受任意目标 URL，状态仍在浏览器端。

Web 课堂若处于可达入口，其大纲、会话和进度命令必须实现，不能登记为 native-only 以绕过兼容检查。浏览器需要 HTTPS 或 localhost 的麦克风条件；麦克风不可用时保留同一课堂的文字提问与老师语音输出。

## 9. 首版范围与实施顺序

1. **最小课堂闭环**：新增版本化大纲、本地会话、全屏课堂和文字插话；Gemini 老师按短教学段自动推进，能够暂停、答疑、显式继续和结束。隐藏旧卡片入口，保留其数据与实现。
2. **语音必需能力**：加入全双工语音插话、回声处理、语音控制意图、连续追问与原声互斥。此步骤完成后才满足本次需求，不能以只支持文字的版本作为最终交付。
3. **可靠性与适配**：跨启动续课、重连、后台暂停、总结、生词本、Windows／Android 真机与 Web TV 兼容验收。

首版不需要数字人视频、教师市场或复杂评分体系。轻量练习是课堂节奏的一部分，可以跳过。

## 10. 验收标准

- 点击章节只进入新课堂，用户界面没有旧卡片入口；旧文件、课件与旧进度仍在。
- 无插话时老师能按大纲自动讲完整节，并正常结束；不会每讲一段都要求点击继续。
- 大纲不包含必须照读的完整教师讲稿；同一教学目标下，老师能自然组织措辞，并根据学生问题换例子、调整解释和衔接，内部断点不造成明显的朗读拼接感。
- 讲课途中可以邀请语音互动；正常回答后反馈并继续，主动提问后等待继续，两种流程不会混淆。
- 每次互动都能用语音或按钮跳过；“只听讲解”停止主动邀请，但保留学生插话。跳过不记答错或已掌握，迟到反馈不覆盖跳过状态。
- 老师外放说话时不回传麦克风录到的老师声音；暂停或开麦按钮能先停下讲解，再接收学生问题，播放结束后的余音和延迟采集帧不得误触发学生发言。
- 文字输入和发送均能暂停讲解；迟到的音频不会再次播放。
- 反复打断、连续追问、原声回听后，主线节点不丢失、不跳跃；答疑结束保持等待，学生说“继续”后恢复。
- 当前小段未播完时不能算学完；“生成完但还没听到”不推进；跳过与完成分别记录。
- 应用退出再进、网络断开再连、Android 后台返回，均能从同一大纲版本的小段恢复，并且不自动突然出声。
- 麦克风拒绝／不可用时可以文字完成同一课堂；静音、离开、结束后没有继续采集或重叠播声。
- 学习语言、母语与 CEFR 对应正确；原文引用和原声区间真实有效。
- 实现时运行邻近的课堂、阅读、Live 测试；跨模块与 migration 按仓库要求扩大到全量测试、Rust 构建／fmt／clippy。Web 跑兼容层测试和 `build:web`，实测 TV 布局及带超时的真实生成。UI 截图验证后删除截图。

最终 Windows release 复验使用合成语音经 MediaStream／AudioWorklet 输入，语音“暂停／继续／跳过”均成功；切到“只听讲解”后自动完成剩余教学，重开课堂恢复完成状态且不自动出声。480×800 窗口无横向溢出、无页面错误。切换互动偏好在当前讲解结束后生效，避免连续暂停／恢复导致控制消息竞态。

原生代码和 migration 更新后需要重启 Windows 客户端。Web 服务端更新需同时部署 `server.js` 与 `classroom-token.js`，设置环境变量后重启服务；本次没有部署服务器、提交或推送。
